# ADR 0003：独立身份、一次性令牌与事务型审批

- 状态：Accepted
- 日期：2026-07-15
- 决策范围：M3 高风险工具审批与安全边界

## 背景

M2 会为经过执行器授权的高风险工具创建审批并暂停，但不能消费审批。M3 必须确保模型
文本、对话上下文和客户端提交的角色或批准标记都不能替代真实的人类授权；审批拒绝后，
原工具调用也不能因恢复或幂等重放而执行。

## 决策

审批由服务端固定端点处理。请求人与审批人必须是同一租户内的不同用户；审批人既要拥有
固定的审批角色和 scope，也必须再次通过目标高风险工具自身的角色与 scope 校验。审批
记录必须关联唯一且仍处于 `AWAITING_APPROVAL` 的工具调用。

审批人先领取短期 decision token。原始 token 只在签发响应中出现一次，数据库仅保存
SHA-256 哈希、绑定用户和到期时间。决定时同时校验租户、用户、常量时间哈希比较、审批
有效期、token 有效期和待决状态；任何终态都清除可用哈希，因此 token 不能重复使用。

批准时，业务副作用、approval/tool-call 终态、workflow checkpoint 和脱敏审计在同一
数据库事务中提交；之后流程从持久化的 `VERIFY_RESULT` 继续归纳。拒绝或过期时，原
tool call 进入终态 `DENIED`，workflow 进入 `NON_RETRYABLE_FAILURE`，不能通过 resume
或原幂等键再次执行。

执行所需的原始、已校验工具参数保留在受控业务记录中；API、工具调用日志和审计只暴露
按固定策略脱敏后的副本。审批 API 不允许提交新的工具参数。

M2 的历史 approval 只保存脱敏参数，无法安全重建可执行输入。迁移为这些既有记录设置
`tool_arguments_available = false`；只有执行器完成 schema 校验并创建的新记录才显式设置
为 `true`。合法独立审批人尝试领取历史记录的 token 时，服务将原 approval、tool call
和等待中的 workflow 置于确定失败终态并要求重新提案，绝不以脱敏参数执行副作用。

## 影响

- 模型只能提出高风险操作，不能授权或改变审批内容。
- 请求人不能自批，token 被绑定到一个独立审批身份且只能使用一次。
- 批准后的副作用和终态不会出现一边提交、一边未提交的数据库状态。
- M2 历史审批不会因缺少原始参数而被错误执行或永久卡在可批准状态。
- provider 重试、指数退避、outbox 和取消语义仍属于 M4，不在本决策范围内。
